# #495 Race socket client: connectToRoom with protocol parsing

- Date: 2026-10-05
- Outcome: `src/features/race/client/socket.ts` gives the web app one typed way into a waiting room: `connectToRoom(url, token)` returns a `RoomSocket` whose `welcome`/`roster` payloads are `safeParse`d with `@fifth-copy/protocol` schemas; failures go to `onProtocolError({ event, issues })` and are never delivered.
- Decisions: no new ADR. `RoomEvents` is derived from protocol `serverEvents`, so a new server event is one schema + one key in protocol. `ConnectErrorReason = RejectReason | "transport"`. Reconnect events live on the Manager (`socket.io`), not the socket.
- Gotchas: `npm run boundaries` has no import-allowlist rule; C5's allowlist is asserted in `socket.test.ts` by reading the source. Parse failures `console.warn` the zod issues only, never the payload or token. `io` is injectable (`opts.io`) for tests.
- Follow-ups: none (#107 renders it).
