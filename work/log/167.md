# #167 Waiting room registry in Redis: open, join/leave, desk allocator, TTLs (MVP)

Date: 2026-10-05. Outcome: delivered (PR #506). Deliver verified all eight contract criteria.

## Decisions
- No ADR. Follows ADR 0008 (a hash per room, TTL 3600 s refreshed on every write, an in-process cache only for `count()`), ADR 0006 and ADR 0012 (`/health` `rooms` drives the drain).
- `open` idempotency: `HSETNX room:<id> openedAt` is the atomic created flag. join/leave are serialised per room by an in-process promise chain, because there is one race server per deployment.
- TTL uses a relative `EXPIRE`, never the injected clock. C5 ages keys with `EXPIRE` by hand because Redis TTLs run on Redis' clock.
- `closed` is true only when this call deleted the keys. A non-member leaving an empty room refreshes its TTL.

## Gotchas
- `scripts/check.sh` unit step now needs Redis: run `npm run db:up` and load `.env` first. Card worktrees can share a Redis db index, so tests delete only their own keys and never run `FLUSHDB`.
- `count()` can over-report after a TTL expiry that had no `leave`. #205 should reconcile it from a SCAN.
- Deliver probes: dropping the TTL refresh in `join` fails both C5 tests. With Redis unreachable or `REDIS_URL` unset, the suite fails rather than skips. No `room:lob_*` keys are left behind.
