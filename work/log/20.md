# #20 Type roles: utilities, Cyrillic fallback, adoption by the primitives and /design

2026-10-06. Delivered (PR #533): six `@utility` type roles in `docs/design/tokens.css` (the only `font-family` declarations of tokens.css and globals.css), Cyrillic falls to Oswald, Button/Field/Alert/EmptyState and `/design` use the roles; 19/19 contract criteria verified by Deliver.

Decisions
- Display and flavour stacks start with the bare face (`--face-stardos`, `--face-special-elite`, set on `<html>` in `src/app/layout.tsx`), not `--font-*`: next/font's fallback face is `local("Arial")` and Turbopack (Next 16.3) ignores `adjustFontFallback: false`, so `var(--font-stardos), var(--font-oswald)` draws Cyrillic in Arial (Deliver CDP probe: Stardos 5 glyphs + Arial 6).
- Bible 7.1 extension: the `Button` primitive is the label-button family (Oswald); the Stardos stamp CTA is a separate pattern.
- `/design` display-lg sample uses a soft hyphen so PAPERWORK breaks only at 375px.

Gotchas
- Any CSS using raw `var(--font-stardos)` / `var(--font-special-elite)` still gets Arial for Cyrillic: use the role tokens (#531).
- `scripts/visual-baselines.sh` cannot build locally (no env in the container build: `Invalid environment variables` at /api/health); baselines came from the CI `update-baselines` dispatch (same pinned image) and the PR `visual` job is green against them.

Follow-ups: #531 (feature CSS modules adopt the type roles).
