# #215 Telex strip and typed sheet with local prediction and paste/copy blocking

Date: 2026-11-02. Outcome: built (UI builder, velocity mode, no Explorer). The parent of #558 and #559: their build was on main; this card adds the integration spec and the one missing hook.

## Decisions
- No ADR. Follows 0007, 0006, 0013.
- C1 needs `data-phase="finished"` on the surface, which nothing carried (the store phase stays `running` until the room ends; the docket uses `data-finished`). Added a pure `surfacePhase(view)` (`before` / `racing` / `finished`) in `src/features/race/view/typed-view.ts`; the telex strip and the typed sheet carry it as `data-phase`. They sit outside `[data-seat-status]`, so `phaseOf` (`[data-seat-status] [data-phase]`) still matches one element. No visual change.
- `e2e/race/typing.spec.ts`: host and guest in a 10-word room (`setHostSettings`); C1 both type the whole strip concurrently; C2 the guest under `emulateMedia({ reducedMotion: "reduce" })` checks the caret (`animation-name: none`, background = the resolved `--color-typing-next-bg` token) and `[data-last]` (`animation-name: none`) on the strip and the sheet, with the motion-on host as the control.

## Gotchas
- The sheet renders `chars[0..cursor]`, so it holds every char only once finished; count against the whole text, not the keys sent.
