# #716 Internal API: web-side nonce replay store

2026-11-03. Race server -> web internal calls now claim their signed nonce once (`web:internal:nonce:<hex>`, `SET NX EX 600`), so both directions of the internal HMAC API refuse replays (401 `replay`).

Decisions: owner DECISION option A (fail closed), recorded as an ADR 0020 amendment. Redis down or slower than 1 s answers a bare 503 and the race server retries (fresh nonce per attempt). `REDIS_URL` is required for web in production (`src/env.ts`); dev/test without it disable the store with one warning. ADR 0019 lists `REDIS_URL` for web.

Gotchas:
- The claim sits after the signature and before JSON/`v` parsing, like the race server: a refused request never burns a nonce.
- CI e2e runs `next start` (production), so Playwright can no longer switch the limiter off with `REDIS_URL=""`; it sets `WEB_RATE_LIMIT=off` instead and the nonce store uses the job's Redis. In production `off` is refused unless `PLAYWRIGHT_E2E=1` (set only by playwright.config.ts).
- A claim that times out may still land later in Redis; that key is never reused, since every attempt signs a fresh nonce.
- `src/server/redis.ts` is the one web Redis client factory (dependency-cruiser `web-redis-only-in-limiter`).

Follow-ups: none.
