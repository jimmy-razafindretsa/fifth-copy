# #518 Internal API: nonce replay protection for signed web -> race server calls

Date: 2026-10-31. Outcome: delivered (PR #717). Deliver verified C1-C3. Pen test: clean (0/0/0). hitl item (PROTOCOL 5a item 4) settled by the owner's DECISION of 2026-10-31 (scope B).

## Decisions
- No ADR (owner decision). Consistent with ADR 0006 point 6, 0008 (nonce keys carry a 600 s TTL), 0020 (Redis error fails closed) and ARCHITECTURE 10 ("HMAC with timestamp and nonce"), which the race-server side now satisfies.
- `PROTOCOL_VERSION` 7. Signed string `${timestamp}.${nonce}.${rawBody}`, built by `internalSignedString` in `@fifth-copy/protocol` so the four signers and verifiers cannot drift. Header `x-fc-nonce`, 32 lowercase hex.
- Missing or malformed nonce answers 401 `bad-signature`. Reuse answers 401 `replay`. The nonce is claimed with one `SET NX EX 600`, and only after the signature verified, so a caller without the secret cannot burn nonces.
- Scope B: both directions sign and require the nonce. Only the race server stores it.

## Gotchas
- Tests that post the shared vector twice now get `replay`. Sign every other request with a fresh nonce (`postSigned` in `internal.test.ts`) and delete `internal:nonce:<vector nonce>` around each test.
- Web and race-server must deploy together (protocol bump). Merge outside class time (ADR 0019).
- Deliver probe on `npm run dev:race`: no nonce 401 `bad-signature`, first 200, same request again 401 `replay`, fresh nonce 200 `created:false`. TTL 584 s; 27 nonce keys, none without a TTL.
