# #926 Shared pre-race loading screen

2026-11-12. After START the room loads before it counts down: phase `loading`, every seat reports `ready` once its text and scene are settled, GO is set for everyone at once when all connected typists are ready or at `LOAD_LIMIT_MS` (30 s).

Decisions: one phase and one decision function (`reviewLoading` in `rooms/lifecycle.ts`); awaited = human desks of the race with a socket open (`presence.isConnected`); ready marks and the limit timer are process state. Protocol 20 (`loading`, `readiness`, `ready`, `welcome.pending`). The scene sees `loading` as `countdown` (no embed change). ADR 0006, 0013, 0017 amendments proposed.

Gotchas:
- Every socket client in tests must answer `loading`, once per race: the harness's `answerLoading` and e2e `simulatedPlayers` do; resending on every `readiness` blows the `ready` budget (5 per 10 s) and gets the socket cut.
- Race-server tests that `host:start` then advance the fake clock must wait for the `countdown` first (`hostStart` in the harness).
- `useRaceStore` selectors must return primitives: the READY count is a preformatted string.

Follow-ups: none filed.
