# #575 Lobby client reloads once on a version connect_error

Date: 2026-10-07. Outcome: delivered (Deliver verdict pass), PR #588.

- A first `connect_error "version"` sets the `sessionStorage` marker `fifth-copy:version-reload` and reloads the page (ADR 0006 point 4); a second refusal with the marker set falls back to the existing `generic` error; `welcome` clears the marker.
- Decision: the side effect lives in `bindRoomSocket` (injected `{ reload, storage }`), so `reduceLobby` stays pure and unchanged. No ADR, no new i18n string.
- Storage unavailable or throwing (blocked site data, private mode) means no marker can be set, so the page never reloads and shows `generic`: no loop possible. Deliver verified this with a throwaway throwing-storage test; the committed suite covers only `storage: null`.
- Mutations checked by Deliver: dropping the marker guard fails C2; dropping the `welcome` clear fails C2; dropping the try/catch fails a throwing-storage test.
- Gotchas: `scripts/check.sh` unit step times out three `scripts/*` CLI tests (db-guard, merged-migrations, rename-user) under parallel load; they pass alone.

Follow-ups: none.
