# #449 prisma generate works without DATABASE_URL (fresh worktrees)

Date: 2026-10-04. Outcome: C1-C7 verified by Deliver (PR #461), 7 of 7 ticked. `prisma.config.ts` declares the datasource only when `DATABASE_URL` is set, so `npm ci` (postinstall `prisma generate`), `prisma validate` and `scripts/check.sh` pass in a fresh worktree with no env, while `prisma migrate status` exits 1 on the missing `datasource.url` without naming any host.

## Decisions
- No ADR proposed. ADR 0002 holds: the URL is still declared in `prisma.config.ts`, read from the env, never invented.

## Gotchas
- The `unit` step now runs `prisma generate`, which rewrites the gitignored `src/generated/prisma`. Do not run vitest and `next dev` in the same tree at the same time.
- An empty `DATABASE_URL=""` counts as unset (no datasource), so DB commands still fail fast.
- C6 was run in the session scratchpad rather than `/tmp/fc-449` (same commands, worktree removed and pruned afterwards).

## Follow-ups
- #453 drops the workflow-level `DATABASE_URL` placeholder in CI (now unblocked).
