# #553 Public repo safety: gates trust only owner comments

Date: 2026-10-06. Outcome: delivered (PR #554, Deliver verdict pass, C1-C8 ticked).

Decisions:
- Trust lives in one pure module, `scripts/lib/trust.ts`. Gates, `latestPickup`, `board.ts get` and `pickup-branch` use only comments by `BOARD_TRUSTED_AUTHORS`. The default is the repo owner. A null author is never trusted.
- Signatures (`PICKUP`, `HANDOFF <role>`, `PENTEST`) count only at the start of a comment. Fields (`verdict:`, `blockers:`) count only in its header block. A missing or unparsable `blockers:` blocks the gate (fail closed).
- `merge.sh` resolves the branch only through `board.ts pickup-branch`. It and `prFor` never select a fork PR (`isCrossRepository`).
- Unfixed pentest findings go to a draft private security advisory. The PENTEST comment carries only the verdict, the counts and the advisory id.

Gotchas:
- GitHub has no repository advisories on a private repo (the API returns 404), so this card's PENTESTs say `advisory: pending`. The findings went to the human directly.
- Merge this before the repo goes public. The card body and BRIEF describe the weaknesses that exist on `main` until then.
- CI did not start on this PR because the Actions billing limit was hit. `merge.sh` waits for green CI, so billing has to be fixed first.
- `is-clean` 200 ms timing test flakes under load (#548).
