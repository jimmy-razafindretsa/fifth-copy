# #691 e2e landing C12: axe document-title fails at random after the language switch

Date: 2026-10-30. Builder log (C1 evidence). Next.js 16.3.8, production build (`npm run start`, as CI), 4-core box.

## C1 reproduction and cause
- CI: in run 40754455160 (shard 1/4) the failing call is `e2e/landing.spec.ts:416`, the second `expectNoA11yViolations` (after the FR click), with `document-title (serious): 1 node(s)`. The first call, on the initial load, never failed.
- Before the fix, locally: `-g "C12" --project=mobile --project=tablet --repeat-each=20 --workers=4`: 0 failures of 80 (5.1 min). Same with `--workers=8`: 0 of 80. The race does not show on an idle local box.
- Probe (Playwright script with a MutationObserver on `<title>`, 375x812, click FR after hydration): 1 run in 25 had no `<title>` at all from 88 ms to 386 ms after the click. The new `<title>` then came back in `<head>`.
- Cause: the title arrives late after the language switch. It is never missing from a page as served. `curl` with a Chrome UA gets `<title>` in `<head>` of the initial HTML in both locales. But `setLocale` calls `revalidatePath("/", "layout")`, so the layout re-renders, and the async `generateMetadata()` of `src/app/layout.tsx` streams again (generate-metadata.md, "Streaming metadata"). When the new tree commits, the old `<title>` is removed. The new one is added only when the metadata resolves. The FR heading is already visible during that gap, so axe could run on a document with no title. On a loaded CI runner the gap is longer.
- So the fix goes in the test (C2, first branch), not in the metadata. Turning off metadata streaming (`htmlLimitedBots: /.*/`) would change the rendering for every page and every user to fix a test wait.

## Fix
- `e2e/landing.spec.ts`: `titled(page, lang)` waits, with `ACTION_WAIT`, for `<html lang>` and for that locale's exact non-empty title. C12 calls it before each axe run (EN on load, FR after the switch). C12 has no theme action: dark comes from the cookie, set before load.
- `e2e/fixtures.ts` is untouched, so `document-title` stays enforced everywhere.

## After the fix
- `-g "C12" --project=mobile --project=tablet --repeat-each=20 --workers=4`: 80 of 80 passed (5.3 min).
