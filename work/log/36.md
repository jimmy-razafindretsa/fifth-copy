# #36 Sign-in and sign-up screens, username sign-up, session and sign-out

Date: 2026-11-04. Outcome: built (UI); C18 (visual direction) waits for the owner.

## Decisions
- No new ADR (0009, 0010, 0001 hold). The session cookie is always set by Auth.js `signIn("credentials", { redirect: false })` from the actions; nothing mints a JWT by hand. Sign-in runs `verifyCredentials` first (for the account id of the merge), so a correct password costs two Argon2id comparisons; a miss costs one either way (no enumeration).
- Guest merge (`merge/merge-on-sign-in.ts`): only a validly signed `fc_guest` merges; a forged cookie is cleared; a failing merge keeps the cookie and never fails the sign-in. Then `flashMerge` and `revalidatePath("/", "layout")` so the root layout's stamp renders.
- `AccountControl` lives in `LandingHeader` (the one site header, bible 14.1): there is no header in `layout.tsx` to mount it in.
- OAuth buttons post `continueWithProvider`, which returns to `/sign-in?error=…` (the callback error banner) until #49 configures the providers.
- `src/proxy.ts` is new: only the `/settings` and `/profile` cookie-presence redirect.

## Gotchas
- `toHaveURL(/\/x$/)` also matches `?callbackUrl=/x`: wait on the pathname.
- The live form exposes `data-hydrated` for specs (useSyncExternalStore, no effect).
- Deliver (2026-11-04): `next dev` gives each route graph its own guest-merge registry, so on a fresh dev server the auth actions saw only identity's steps and `mergeGuestInto` failed closed (fc_guest kept, C12 red when run alone). `src/app/(auth)/merge-steps.ts` imports every feature that registers a step; `merge-steps.test.ts` fails when one is missing.

## Follow-ups
- discovered (to file): `verifyCredentials` (#38) lets a control or NUL character reach Postgres (generic error, no leak); move the control-character guard of `usernameLookup` into `src/lib` and reuse it there.
- discovered (to file): the merge registry relies on side-effect imports per route graph; a central registration that every `mergeGuestInto` caller (OAuth #49) shares would remove the per-route list.
- Otherwise none (throttling and sign-out revocation stay #87; recovery code #46; OAuth #49)
