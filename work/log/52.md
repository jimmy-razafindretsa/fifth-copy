# #52 OAuth avatar import

2026-10-06. `importOauthAvatar(userId, imageUrl, deps?)` turns an OAuth provider picture into a stored avatar through `storeAvatar` (centered square crop); it never rejects and returns `imported: false` with a reason code.

Decisions:
- SSRF guard in `fetch-provider-image.ts`: https only, exact hosts `avatars.githubusercontent.com` / `cdn.discordapp.com` (constant), default port, no userinfo, `redirect: "error"` plus a 3xx check, one 5 s deadline raced against headers and every body read, Content-Length hint plus a streamed 5 MB cap, `image/*` type.
- `storeAvatar` accepts `crop: "center"` (resolved after the oriented dimension checks).
- DB write is `updateMany where avatarKey null` (`actions/oauth-avatar-users.ts`, not a Server Action); a lost race deletes the import's files.
- Warnings: `oauth_avatar_import_failed` + reason only.

Gotchas: not wired into sign-in yet (no `src/server/auth/auth.ts`); that is #539. #49's `profile()` must emit URLs on exactly those two hosts.
