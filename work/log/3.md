# #3 Scaffold: src/ architecture, strict TS, lint, format, boundaries, env

Date: 2026-10-03. Outcome: delivered (PR #448); all five contract criteria verified by Deliver.

## Decisions
- ADR 0001 accepted in this PR (consistent with ARCHITECTURE section 5, ADRs 0005 and 0011). ADR 0004 left proposed for #5.
- `prisma-only-in-server` now allows `src/features/*/jobs/**` (accepted ADR 0011); AGENTS.md aligned.
- C1 and C4 have an executable negative form: `scripts/gates.test.ts` (depcruise over a temp fixture tree, ESLint `lintText` probes).

## Gotchas
- Worktrees have no `.env`: export `DATABASE_URL` (any `postgresql://` URL) before `npm install` / `prisma generate`, else typecheck fails on `src/generated/prisma` (hazard line added to AGENTS.md).
- `src/env.ts` is `server-only` and `process.env` is banned elsewhere in `src/`: client code has no sanctioned way to read `NEXT_PUBLIC_*` yet.
- The depcruise fixture in `gates.test.ts` covers ui->features but not ui->server; ui->server is covered by `components-no-server` (depcruise) and the ESLint probe.

## Follow-ups (for the Picker, from the BRIEF)
- `prisma generate` independent of `DATABASE_URL` (or worktree `.env` setup).
- `src/env.client.ts` for `NEXT_PUBLIC_*` in client components.
