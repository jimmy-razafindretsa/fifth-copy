# #552 Landing live feed plays a recorded video loop

2026-10-06. The landing live feed is a lazy, decorative `<video>` (LazyVideo) playing recorded loops of the bible's Full Lobby scene instead of the WebGL embed; clerk and medal stay 3D.

Decisions: no ADR. Loops recorded in Playwright's bundled Chromium (seeded RNG, virtual rAF clock, MediaRecorder MP4 avc1 + WebM VP9), no ffmpeg, no new dependency. FREE VIEW = one 16 s orbit via the scene's `?orbit=` hook (bible 15); film grain not baked (bible 7.8). Reduced motion renders no `<source>` at all (poster only, zero bytes).

Gotchas:
- Media uses Range requests and cancels them itself: e2e counts distinct clip URLs, and `e2e/fixtures.ts` tolerates `ERR_ABORTED` GETs under `/media/live-feed/` only.
- Chrome's MP4 is fragmented; headless shell may report a short duration before the file loads. Safari playback was not machine-checked (no WebKit installed).
- Re-record only when the scene changes (`npx tsx scripts/record-live-feed.ts`); each re-record adds ~7 MB to history.
- C9 had no landing visual baseline to update; CI `visual` did not run on the PR head (GitHub billing).

Follow-ups: nit, `setViewMessage` and the live-feed `frameTitle` label are now unused.
