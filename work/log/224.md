# #224 Machine keys: viewer layout, press and wrong-key motion

- Date: 2026-10-22. Outcome: the seat-view machine draws the viewer's layout. The UI language picks it until #66 (fr gives CSA, en gives US QWERTY). Its keys press, shake on a wrong key (again on a repeat), and read disabled once you finish. Reduced motion moves nothing. Deliver verdict: pass, C1-C8 ticked.
- Decisions:
  - `machineRows` is an async `"use server"` function, following `getRaceSeat`. The race index reaches client graphs only as a server reference, so the server-only identity barrel stays out of them. The input is a zod `strictObject` and the output is public static data, so this is not a security concern.
  - FR_CA caps read `ç` and `è` on its dead keys, and its ANSI `<` keeps the first row distinct from CSA (bible 7.7a).
  - `lkShake` is the Locker reference keyframe, on `translate`.
- Gotchas:
  - The C8 duration allowlist also holds `1.3s` (#560's `lkPulse`, already on main).
  - A Block jam flip without a new key presses the last key again once, and repeats of the same key within 120 ms keep the cap down. Both are decorative.
  - `prediction.spec` C6 is load-sensitive locally. With the dev server and 1 worker: 5 of 6 runs took 21-25 ms, and one took 160 ms at load avg 32. A scheduling stall, not a shift caused by this PR. It is green on CI.
- Not run by Deliver: a client-chunk grep of a production build (the builder's PR note covers it; code review agrees).
- Follow-ups: #66 fills the `layout: null` seam and should review the FR_CA modelling.
