# #654 Seat view applies host settings changed after the guest sat

- Date: 2026-10-24
- Outcome: the race store applies the room's `settings` broadcast, so a guest seated before the host switches to Block races under Block (input `data-mode`, local jam, prediction). Deliver verdict: pass (PR #670).

## Decisions
- No ADR. One `RaceEvent` (`settings`), one `reduceRace` case (replace `settings`, nothing else), one `socket.onSettings` binding. The prediction is not rebuilt on `settings`: the server accepts `host:settings` only while waiting, and `countdown` builds the prediction from `state.settings`.
- The hand-rolled `RoomSocket` fakes in `connect-seat.test.ts` and `resume-key.test.ts` gained `onSettings` (listener count 9 -> 10). Outside the BRIEF's touch list but in scope: the binder now calls it, so every fake must provide it.

## Gotchas
- Any new `bindRaceSocket` listener means updating those two fakes and the listener count in `connect-seat.test.ts`.
- The e2e must show `SEAT VIEW · DESK nn` before `setHostSettings`, so the guest's welcome predates the broadcast (`race(..., { settingsAfterSeat: true })` in `e2e/race/block-mode.spec.ts`).
- Deliver negative runs: with the main `store.ts`, 4 unit tests fail and the live C3 case fails with `data-mode` "continue".
