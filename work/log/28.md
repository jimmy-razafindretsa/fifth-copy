# #28 Reduced motion and flash safety rules

2026-10-06. Outcome: one motion setting (`prefers-reduced-motion` or `<html data-motion="reduce">`) drives `--motion-*` tokens, every keyframe's reduce block and `useReducedMotion` / `MotionSafe`; flash rule written in `docs/design/components.md` "Motion" and bible 8. PR #541.

Decisions: no ADR. `--motion-duration-slam` 180ms is contracted but bound to nothing: bible 8 slams are 0.3-0.45s, so #26 reconciles the value. The /design demo is a server component (MotionSafe is the client leaf); the demo pulse is transform-only so it models the flash rule.

Gotchas:
- No global clamp any more: every keyframe needs its own reduce rule under BOTH selectors, at a specificity that beats the rule that starts it. Deliver found `.char[data-last="true"]` (fcPop) outranking the media block's `.char`; fixed in d94340c with an e2e test in `e2e/landing.spec.ts`.
- #66 must render `data-motion` on the server (like `data-theme`): a client script editing `<html>` before hydration is a React attribute mismatch. The e2e sets it after hydration.
- `data-motion` does not cross the 3D iframes; #272/#288 pass it through the embed bridge.
