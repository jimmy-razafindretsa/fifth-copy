# #452 db-guard refuses multi-host URLs

Date: 2026-10-04. Outcome: C1-C5 verified by Deliver (PR #468), 5 of 5 ticked. `scripts/db-guard.sh` now refuses (exit 1, static message, no URL echoed) any authority whose host part after the last `@` contains `,` (libpq multi-host) or `%` (percent-encoded host), before the host compare, the query loop and the allow-list.

## Decisions
- No ADR proposed. ADR 0003 and 0004 hold: same guard, same callers, text-only decision.

## Gotchas
- Without the fix only the two local-first, port-first multi-host URLs passed the guard; the other new refusal cases already failed the host string compare by accident. The explicit branch keeps a decoding or multi-host parser from getting ahead of the guard.
- `%` in the authority also refuses IPv6 zone ids (`[fe80::1%25en0]`): fail closed by design. Percent-encoded passwords (before the last `@`) and commas in query values or fragments are still accepted.
- A designated host cannot legitimise a comma authority: `DB_GUARD_ALLOWED_HOSTS` is itself split on `,`.
