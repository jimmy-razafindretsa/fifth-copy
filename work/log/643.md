# #643 Seat view clock offset refined by ping/pong after each welcome

2026-11-02. After each `welcome`, `bindRaceSocket` (`src/features/race/client/store.ts`) sends 5 pings 600 ms apart on the injected timer and sets the store's `clockOffset` to `bestOffset` of the pongs received so far (`src/features/race/client/clock.ts`); a pending GO is rescheduled on the refined offset. `RoomSocket` gains `sendPing` / `onPong`.

Decisions:
- No wire change: `pingSchema`, `pongSchema`, `serverEvents.pong` and the race server's answer already existed (#172's). No `PROTOCOL_VERSION` bump.
- `sendPing(sent = Date.now())`: the binder passes `timer.now()`, so `sent` and the receipt time come from the same (injected) clock; the default keeps the contract's `Date.now()`.
- New `RaceEvent` `{ type: "clock", offset }`; dispatched on the first pong of a round and whenever the best round trip changes the offset, not on every pong.
- A pong counts only when its `sent` is one of the current round's pings: a new `welcome` (reconnect) drops the previous round's late pongs.
- Five pings 600 ms apart (`PING_ROUND_COUNT`, `PING_ROUND_INTERVAL_MS`): the card first said 100 ms, which breaks ADR 0020's `ping` budget (2/s per identity; 3 refusals disconnect, so the e2e saw a line-cut). Owner chose 600 ms on 2026-11-02 (contract reworded). The round lasts 2.4 s, inside the 3 s countdown; a pong after GO still corrects the offset.
- The spacing holds across rounds: a welcome less than 600 ms after the last ping (a reconnect mid-round) delays the new round's first ping, so no 1 s window ever holds 3 pings.

- Deliver fix cycle 1: `pongOffset` is fractional (`x.5`), and `nextStepIn` assumed whole ms (at `msToGo` 1000.5 the "1" never showed). Now `nextStepIn` is exact for fractions (`msToGo - (ceil(msToGo/1000) - 1) * 1000`), and the binder rounds the refined offset to whole ms before dispatching (C1's `pongOffset` stays as contracted).

Gotchas: the existing #214 tests that count pending timers now advance past the ping round first (the pings share the injected timer). The lobby's fake `RoomSocket` gains the two methods; the lobby store binds neither.

Follow-ups: periodic re-sync during a race, the timer tube (#240) and keystroke `t` (#559) read `clockOffset` and get the refinement for free; ARCHITECTURE 7.3 still names #172 (an architecture session's).
