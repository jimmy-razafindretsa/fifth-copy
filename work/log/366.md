# #366 Bots as server race participants

2026-11-02. Bots type: at GO every bot desk gets a driver (`services/race-server/src/rooms/bot-driver.ts`) that asks `nextBotKeystroke` for its next key and feeds it through `ingest` on the server clock. No wire change (`PROTOCOL_VERSION` 7), nothing new in Redis.

Decisions:
- `createBotDrivers({ clock, scheduler, rng, next?, profileOf?, ingest? })` -> `start(runtime, bots, language) / stop(lobbyId) / close() / active(lobbyId)`. One pending handle per bot; Redis-free, Socket.IO-free (reusable by a load test and #128).
- Levels come from the members hash: `registry.botLevels(lobbyId)`, read in `goRunning` under `withRoom`, passed as `init.bots` to `onGo`.
- Stops: `onEnding` (sync, before the ranking), `onEnded`, `onRestart`, `onClosed` (void, room closed, Redis lost), `close()`. The fire guard also checks `phase`, `ending` and desk status.
- `chars` cached per desk by the effective text string: an overlay (C6) is picked up on the next key.
- Delays are real ms, never fast-clocked; the server rng (`createRaceServer({ rng })`) also drives the bots.

Gotchas:
- Deviation from the BRIEF: delays are rounded to whole ms and `t` floored. Float delays made the fake clock fractional, so `finishedAt`/`durationMs` failed `raceMsSchema` and the outbox retried forever. With the system clock `t` was already integer; every level's trace still passes `analyseTrace`.
- `rooms/bots.test.ts` (#156) expected a bot to sit at cursor 0 until the timer; it now finishes first (seeded rng).
- Dawn report `data-place` is zero-padded (`"02"`).
