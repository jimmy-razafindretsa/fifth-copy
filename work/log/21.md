# #21 Self-host fonts with next/font

- Date: 2026-10-05. PR #510.
- Outcome: the six brand families (Stardos Stencil, Oswald, IBM Plex Mono, Special Elite, Courier Prime, VT323) load through `next/font/google` in `src/app/layout.tsx`; `@theme` exposes them as `--font-{display,label,typing,flavour,body,device}`; Geist and `--font-sans`/`--font-mono` are gone; body copy is Courier Prime 16px / 1.55. Six `/design` baselines regenerated.
- Decisions: no ADR. `--font-*: initial` mirrors the `--color-*: initial` reset so Tailwind's default families really disappear. Flavour fallback is `ui-monospace, monospace`. Design bible 4 records Special Elite and VT323 as the flavour/device extension.
- Gotchas: `document.fonts.check()` is true when no face matches, so a literal check is vacuous; `e2e/fonts.spec.ts` resolves the family from its CSS variable and asserts `document.fonts.load()` returns loaded faces first. Build and dev need outbound HTTPS to Google Fonts (build time only). `scripts/visual-baselines.sh` now passes CI's throwaway `RACE_TOKEN_SECRET` so `npm run build` passes `src/env.ts`.
- Follow-ups: #511 (stop preloading flavour and device fonts on every route; 18 woff2 preloads today).
