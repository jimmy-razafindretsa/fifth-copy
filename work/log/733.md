# #733 Worker runner: src/worker entry, JobRun table, advisory-lock scheduler, Railway worker service

Date: 2026-11-09. Outcome: the ADR 0011 worker runs. `src/worker/main.ts` loads `src/env.ts`, runs the jobs of `src/worker/registry.ts` (`heartbeat`, every 5 min) through `scheduler.ts`, records each run in `JobRun` (`prisma/schema/jobs.prisma`), drains on SIGTERM and listens on nothing. Railway service `worker` from the repo root (`src/worker/railway.json`).

## Decisions
- Advisory locks go through a dedicated `pg` session (`src/worker/locks.ts`), not Prisma's pool: a session lock must be taken and released on the same connection. Key `hashtext('fifth-copy:job:<name>')`.
- After taking the lock the scheduler re-checks "due", so a replica that ticks just after another finished does not run the job twice.
- Prod entry is an esbuild bundle (`scripts/build-worker.mjs`, `react-server` condition for `server-only`); npm deps stay external. Dev uses `tsx --conditions=react-server`.
- ADR 0019 amended (worker service, variables, scope); ADR 0011 unchanged.

## Gotchas
- A new Prisma model without a user relation goes into `MODELS_WITHOUT_USER` (identity merge coverage test).
- The worker does not migrate; on a first deploy before web's pre-deploy it logs tick errors and retries each minute.
