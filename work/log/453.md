# #453 CI prepares the test DB via scripts/test-db.sh (ADR 0003)

Date: 2026-10-04. Outcome: C1-C5 verified by Deliver (PR #474), 5 of 5 ticked. `e2e` and `visual` now run `scripts/test-db.sh` (guard, then `migrate deploy`) with `TEST_DATABASE_URL`; the workflow-level `DATABASE_URL` placeholder is gone, so only jobs with `services.postgres` define it and `check` runs with no database URL. The `migrations` job keeps its steps byte-identical and gains only a job-level `env.DATABASE_URL`.

## Decisions
- No ADR proposed. 0003 and 0012 (accepted) govern; 0004 (proposed) covers Vitest over `scripts/**/*.test.ts`.
- In CI the throwaway service DB `app` is both app DB and test DB (card decision; ADR 0003 names `app_test` only for local).

## Gotchas
- `scripts/ci-workflow.test.ts` states the rules over "jobs with `services.postgres`", so a new DB job must follow them or the test fails. Mutation check: putting back the workflow `DATABASE_URL` and `e2e`'s `prisma migrate deploy` fails exactly the C1 and C2 cases.
- The C5 `test-db:` marker only prints while `prisma/migrations` does not exist (#472).
- Under heavy machine load (load average 70-120) the spawn tests in `deploy-smoke.test.ts` and `see.test.ts` time out locally; they pass alone and in CI (#469).
