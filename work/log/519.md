# #519 e2e: landing join action POST reported net::ERR_ABORTED

Date: 2026-10-05. Outcome: the failed-request guard in `e2e/fixtures.ts` exempts only an aborted server-action POST answered 2xx `text/x-component`. Every other failed request still fails the test.

## Root cause (C1): the browser client, below Next/React. Not the test's ordering, not the fixture.
- Reproduced under `next start`. The first server-action POST after a fresh server start is aborted about half the time; later POSTs never are. Mobile flakes most.
- Server: a raw HTTP client gets the two Flight rows and the chunked terminator within 1 ms.
- Chromium net-log: the network service reads the full gzip body to EOF, and `REQUEST_ALIVE` ends with no error.
- CDP: all 101 body bytes arrive (`dataReceived` 66 + 35), then `loadingFailed {canceled: true}` follows within ~5-30 ms.
- No JS cancels it. Patched `ReadableStream`/reader `cancel`, `releaseLock` and `AbortController.abort` never fire, Next's action `fetch` has no signal, and React Flight reads to `done`.
- Holding a reference to the `Response` or forcing GC changes nothing.
- So Blink reports a renderer-side cancel of a completed load. The UI already has the result.
- Subscribing to more CDP Page/Network events masks it, so this is a timing race.

## Gotchas
- `request.response()` still resolves for these aborted requests, so the guard checks status and content type.
- The guard check is async. The fixture awaits `settle()` before it asserts.
