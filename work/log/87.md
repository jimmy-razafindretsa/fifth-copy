# #87 Account security hardening: cookies, CSRF, no-email guard, throttling

- 2026-11-09, builder: partial. C1-C4 and C8 built; C5 wired on ADR 0020's Redis limiter; C6 and C7 and the `MemoryLimiter` half of C5 not built (contract predates ADR 0020, see the card's HANDOFF).
- Cookie policy in `src/server/auth/cookies.ts` (`cookieFlags`, `secureCookiesFor`): Auth.js runs with `useSecureCookies` in production, so the session cookie is `__Secure-authjs.session-token` even over the production build on http://localhost (Chromium accepts it there). e2e helpers match the session cookie by suffix.
- Sign-out bumps `tokenVersion` (ADR 0009 amended). Auth.js's own `/api/auth/signout` still only deletes the cookie; the UI uses the action.
- Budgets (ADR 0020 amendment #87): sign-in 30/15 min per client IP then 10/15 min per account, also on `/api/auth/callback/credentials`; sign-up 10/h per IP; avatar 5/min per viewer. Client budgets use `requestIpSubject()` so a fresh guest cookie never resets them. Successful sign-ins count.
- Gotcha: Chromium keeps its own `Origin` on `route.continue`; forge it with `route.fetch` + `fulfill` (e2e/auth/csrf.spec.ts).
- Follow-up: throttle guest creation (`updatePreferences` -> `ensureGuest`, #66).
