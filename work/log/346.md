# #346 Text corpus: Prisma model, licence-checked import, load

2026-11-04. The `Text` table (`prisma/schema/texts.prisma`, migration `20261104013604_text_corpus`, additive) holds the corpus; `scripts/import-texts.ts` loads the content files into it and `startRace` reads it through `loadCorpusProvider`.

Decisions: proposed ADR 0021, a server-only `server.ts` entry per feature beside the client-safe `index.ts` (dependency-cruiser accepts it, forbids it from components). Words mode keeps the frequency lists of the files; only `sentences` come from the rows. Under 20 rows for a language the files serve it, so CI and a fresh production database need no import.

Gotchas: DB tests that write `Text` rows run in a rolled-back transaction, so parallel test files keep an empty table and `files:` refs. The provider cache is per process (5 min): call `clearCorpusCache` in tests. A new model without a user relation goes into `MODELS_WITHOUT_USER` (guest merge registry) or the merge coverage test fails. db-guard refuses the Railway host unless `DB_GUARD_ALLOWED_HOSTS` names it for the one command (`docs/ops/runbook.md`).

Follow-ups: none.

## ADRs
- 0021 (feature `server.ts` entry): accepted by Deliver (roles/deliver.md 3b). It extends ADR 0001 (explicit, machine-checked public entries) without superseding it and matches ARCHITECTURE 7 and 8.2 as updated here. Deliver added `feature-index-not-server-entry` so no `index.ts` can re-export a `server.ts`; a `"use client"` file outside `components/` is still caught only by `server-only` at build time.
