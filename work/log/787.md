# #787 Session viewer resolver

2026-11-03. `getViewer()` now resolves the Auth.js session before the guest cookie; a JWT whose `tokenVersion` no longer matches `User.tokenVersion` resolves to no viewer, and `/api/auth/session` answers `{}` for it.

Decisions
- `src/server/auth/session.ts` is pure (`createSessionResolver`, `accountViewer`); `resolvers.ts` wires `auth()` and one `findUnique` by `sub`.
- The Auth.js `jwt`/`session` callbacks stay DB-free (they run wherever `auth()` runs, a future proxy included). The revocation check lives in `accountViewer`, shared by the resolver and the `/session` GET wrapper (moved from `auth.ts` to `handlers.ts`), which expires a rejected session cookie instead of refreshing it.
- `getSession` skips `auth()` when no `authjs.session-token` cookie is present: guests pay no JWT decode and no extra read.

Gotchas
- `session.user.tokenVersion` defaults to 0 in the session callback, so a token minted without the claim matches a row at 0. Every provider path must keep setting `user.tokenVersion` (#49).
- e2e signs `fc_guest` itself from `AUTH_SECRET` (job-level env in CI).

Follow-ups: none.
