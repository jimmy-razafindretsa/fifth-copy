# #38 Auth.js Credentials core (split 1 of 3): Argon2id and verifyCredentials

2026-11-03. Outcome: `src/server/auth` hashes and verifies passwords with Argon2id (`@node-rs/argon2`, m=19456 t=2 p=1) and `verifyCredentials` resolves a username and password to `{ id, name }` or `null`.

Decisions: no new ADR (ADR 0009 unchanged). `normalizeUsername` moved to `src/lib/username.ts`; `features/identity/schema.ts` re-exports it so existing imports stay. `verifyCredentials` takes `unknown` (zod-parsed) so the Credentials provider's `authorize` can pass its raw input.

Gotchas: `DUMMY_HASH` in `password.ts` must be a real PHC string with the same parameters as `hashPassword` (a test compares them); a fake or malformed one fails fast and reopens the username-existence timing leak. Change both together. `Algorithm` from `@node-rs/argon2` is an ambient const enum, unreadable under isolatedModules: `password.ts` uses the literal 2. Next lists `@node-rs/argon2` in its default server external packages, so no `next.config` change is needed. Errors thrown here take no arguments, so they never carry a password or hash. Throttling is not here (#87).

Follow-ups: the Auth.js config card (split 2) wires `verifyCredentials` into the Credentials provider.
