# #4 Prisma 7 + local Postgres, db-guard, test DB, seed

Date: 2026-10-03. Outcome: delivered (PR #451); all five contract criteria verified by Deliver.

## Decisions
- ADRs 0002 and 0003 accepted in this PR (consistent with ARCHITECTURE sections 5, 9.2, 11 and accepted ADRs 0001, 0011, 0012), following the #3 precedent for card-governing ADRs. 0004 stays proposed for #5.
- `scripts/db-guard.sh` takes the host after the last `@` of the authority and fails closed on query keys that redirect the connection (`host`, `hostaddr`, `port`, `service`, `servicefile`, `dbname`, `socket`, any percent-encoded key).
- `docker-compose.yml` has `name: untitled` (Picker's call for the human): every worktree shares one stack and the `untitled_pgdata` volume.

## Gotchas
- `npm run db:up` from a worktree recreates `untitled-postgres-1` (the `prisma/docker-init` bind mount is per checkout); data is kept. Re-run it from the main checkout after removing a worktree.
- `scripts/test-db.sh` only exercises its no-migration branch until the first migration lands.
- The guard accepts a comma multi-host authority (`localhost:5432,remote:5432`); harmless today since pg-connection-string 2.14.1 rejects it as an invalid URL, but worth failing closed.
- CI applies migrations with `prisma migrate deploy` directly, not via `scripts/test-db.sh` as ADR 0003 describes.
