# #961 Personnel file: per-key read model (key file, letter pairs, fixtures)

2026-11-17. The stats feature answers "how does this typist do on each key and letter pair?" as a `KeyFile` built from `CharStatDaily` and `BigramStatDaily` (#312, ADR 0024) only: `getKeyFile(viewer)` reads the viewer's rows in three queries, the pure `keyFileOf(charRows, pairRows)` does the rest. No UI (#962-#965, #324 build on it).

Decisions: a key's speed is `12000 * timedHits / totalMs`; layouts summed; the window is the 40 latest stats days with character rows and the pair rows of the same days (summed per pair in SQL). `learningRate` reuses `trendLine` of `performance-curve.ts` over the series from its 15th-last present value, so its unit is WPM per file day (one entry of `days`), the x axis of the key's graph, not per calendar day. `averageWpm` needs one timed hit (no 3-hit floor: the floor is per day, for the series); `state` is `none` without it. Pair ties on speed put a pair without timed hits after the timed ones.

Gotchas: fixtures round `totalMs` to whole ms like the stored column, so tests compare speeds with `toBeCloseTo`. Exported via `index.ts` like `getCensus` (the contract's wording), not `server.ts`.
