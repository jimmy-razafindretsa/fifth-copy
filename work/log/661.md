# #661 Race and lobby clients: handle a server-side disconnect

2026-11-09 · ui (Opus). Outcome: a server-side close (`io server disconnect`) ends the race page on the lost line and a seated lobby on the error line (generic sentence); a transport drop marks the race store reconnecting at once and holds `keys` until the next welcome.

Decisions:
- `RoomSocket.onTransportDisconnect` beside `onServerDisconnect` (#732); both stores bind them.
- `RaceState.keysHeld`: set by the drop, a reconnect attempt or a transport error, cleared by `welcome`; `selectCanType` reads it, `createTyping` parks batches while it is set and sends them after the welcome (counted `sent` only then, so the welcome's reconcile types them again on top).
- Lobby: a server close before the first seat stays the late-join hold's (#732); after the seat it is `error: "server-disconnect"` (copy: generic). The test "a server disconnect after the seat is not the hold's" now expects that error (it pinned the old stuck state).
- C3 was already met by #235 (`ended { void }` is the lost room); a #661 test pins it.

Gotchas: see.ts evidence used a throwaway socket.io stub on the card's race port (welcome, then `disconnect(true)` or `io.close()`); not committed.
