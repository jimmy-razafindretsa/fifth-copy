# #103 Lobby actions: create private lobby, join by code, mint race token, open room over HMAC

Date: 2026-10-05. Outcome: delivered (PR #514). Deliver verified all seven contract criteria; the integration tests ran on the test DB with the race-server stub.

## Decisions
- No ADR. Follows 0001, 0002, 0003, 0006 (token claims, HMAC `${timestamp}.${rawBody}`), 0008, 0009 (`ensureGuest` on first write, token minted in an action).
- A 200 whose body fails `openRoomResponseSchema` counts as `race-server-unavailable`.
- Room codes are drawn with `node:crypto` `randomInt`, because the code is the MVP's only secret. `generateRoomCode(rng)` stays pure.

## Risks accepted (PENTEST #103)
- major: room-code enumeration is free because no limiter exists. The code space is 138 M; with 50 open lobbies, a hit is expected after about 1.4 M tries. Not reachable yet: no route imports `@/features/lobby`. The owner is #120 (limiter #207), and it must land before #107 exposes the join form.
- minor: `ensureGuest` runs before `openRoom`, so a failed `createLobby` still creates a guest (known from #32).
- minor: if the race server hangs after receiving the request, it can keep a ghost room for a deleted lobby. The HMAC has no nonce, so a captured request can be replayed for 300 s. Owners: #144/#145 (`closeRoom`) and the protocol.

## Gotchas
- `new URL(path, baseUrl)` drops any path prefix in `RACE_SERVER_INTERNAL_URL`, so keep that variable as origin only.
- The join and mint fixtures use `JNB-730x`, never `KGB-4821`, because `lobby-model.test.ts` deletes `KGB-4821`.
