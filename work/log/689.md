# #689 Make visual-baselines.sh mktemp portable to GNU/Linux

Date: 2026-11-02. Outcome: built (velocity mode, Builder BRIEF). Also covers duplicate #726 (proxy part).

## Decisions
- Temp archive in `mktemp -d "${TMPDIR:-/tmp}/visual-src.XXXXXX"` (GNU and BSD accept it), removed by an EXIT trap; the old line also leaked the bare template file on every run.
- Behind an HTTPS proxy: proxy vars forwarded by name (values never on the docker command line), `localhost,127.0.0.1` prepended to NO_PROXY, CA from `VISUAL_CA_BUNDLE` or `NODE_EXTRA_CA_CERTS` mounted read-only as `NODE_EXTRA_CA_CERTS` (adds to, never replaces, Node's store; no `npm_config_cafile`).
- A loopback proxy is unreachable from a bridge network, so only then the container uses `--network host`: Postgres/Redis on their published localhost ports, web/race on the loaded `PW_PORT`/`RACE_SERVER_PORT` (worktree ports, no collision). No proxy: the compose-network path is unchanged (macOS, CI-like Linux). Pinned image unchanged.

## Evidence
- `scripts/visual-baselines.sh --check` on this Linux cloud host (worktree `.env` loaded, main's baselines): host network via proxy, `npm ci` + both builds OK, 6 passed (design page, 3 viewports x 2 themes), 2m05s, no temp leftovers.
- `scripts/check.sh` all green.

## Gotchas
- `docker compose up` from a worktree recreates the shared `untitled-postgres-1` (its `./prisma/docker-init` bind mount resolves per checkout); data survives in the named volume but parallel cards see a short DB drop. Pre-existing, not changed here.
- The bridge (no proxy) branch was not run end to end here (no direct egress); its code is unchanged apart from the temp dir.
