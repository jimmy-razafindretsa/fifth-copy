# #251 Tablet seat view layout

Date: 2026-11-02. Outcome: built (ui session, velocity mode). `use-on-screen-keyboard.test` passed (11). `e2e/race/tablet.spec.ts` C2-C4 passed (tablet project), with `seat-shell` and `race-card` still green. `check.sh` was all green. `visual-baselines.sh --check` passed with no baseline change, because no baseline covers `/race/*`.

## Decisions
- No ADR. Follows 0013 (HTML layer) and 0001. `watchOnScreenKeyboard(env)` is a pure core with an injected `visualViewport`, clock and timers; `useOnScreenKeyboard()` wraps it. `innerHeight` is read at the moment of focus. Browsers that resize the layout for the OSK (Android's default, and Playwright's emulation) shrink `innerHeight` too, so a reading taken during the resize would never trip the 70 % rule.
- `SeatLayout` stays a server component. The seat view passes it a client `frame` (`seat/seat-frame.tsx`), which carries `data-osk` and `data-orientation` around the server-rendered slots. The frame lives in `seat/` because `components/` may not import `client/` (#558 C10 import test).
- Bible 14.3 extension "Tablets and the on-screen keyboard": with `data-osk="open"` the teleprinter folds away and the typing surface moves up under the telex, with the card and tray rows after it. The fold has no motion.
- C2 was already met on main by #226 (compact race card at 768/1024) and #240 (compact nixie). This card adds the running-phase check in both orientations.
