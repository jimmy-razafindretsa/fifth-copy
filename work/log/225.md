# #225 Nixie WPM and place counters

- Date: 2026-10-31
- Outcome: the seat view's nixie tubes show your live clean WPM (engine `cleanAndAdjustedWpm(...).clean`, ADR 0016) and your place `01 / 02` from the server's `ranks`; copy under `race.counters.*`.

## Decisions
- No ADR. `selectWpm` composes the engine's `elapsedFor` + `cleanAndAdjustedWpm` over the corrected clock (`now + clockOffset - race.t0`), frozen at the engine's `finishedAt`; no second formula.
- WPM is a sampler (`createWpmSampler`, 250 ms on an injected timer, ticking only while you type in a running race); keystrokes never render it. Place is read as two primitives, so it re-renders only when it changes.
- Contract C1 says place 0 is "(shown `--`)"; bible 7.11/14 say `00 / n` before the start (seat-shell e2e asserts it). The bible wins on visuals; the selector returns `place = 0` as C1 requires. Accepted by Deliver as non-blocking.

## Gotchas
- `imports.test.ts`: the live leaf is an allowed store reader (`../client/use-race-store` only), like `typing-machine-live.tsx`.
- Until #240 adds `ended`, a timer end while still typing keeps the WPM on the live clock; cap it in `selectWpm`.
