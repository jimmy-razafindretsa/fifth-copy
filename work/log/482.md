# #482 Viewer contract: identity types, getViewer and requireViewer stubs

Date: 2026-10-04. Outcome: delivered (PR #496); all five contract criteria verified by Deliver.

## Decisions
- No ADR. Follows ADR 0009 (identity only via `getViewer()` in `src/server/auth`) and ADR 0001.
- `Viewer`/`ViewerResolver` live in `src/server/auth/types.ts`, not `viewer.ts`: `viewer.ts` <-> `resolvers.ts` tripped `no-circular`.
- No `src/features/identity/types.ts`: `Viewer` must live in server (server cannot import features), so `features/identity/index.ts` only re-exports.
- C3 "carries no request data" is checked as: message `Unauthenticated` and `Object.keys(err)` empty (`name` is a prototype getter).

## Gotchas
- `src/server/auth/resolvers.ts` is the only extension point: #38 prepends the session resolver, #32 appends the guest one. Expect a trivial merge between them.
- `viewer.ts` is `server-only`: client components may only `import type { Viewer }` from `@/features/identity`.
- Deliver probes: an upward import in `src/server/auth` fails `npm run boundaries` (server-no-upward); a non-short-circuiting chain fails `viewer.test.ts`.
