# #651 Landing always starts in light mode

- Date: 2026-10-20
- Outcome: built (owner request). The landing root carries `data-default-theme="light"`; the OS-dark block of `docs/design/tokens.css` (and the wordmark swap in `hero.module.css`) now reads `:root:not([data-theme="light"]):not(:has([data-default-theme="light"]))`, so a dark OS no longer turns the landing to Night shift. The landing's NIGHT SHIFT toggle treats a missing cookie as light.

## Decisions
- Landing only, not site-wide: other pages keep following the OS without a cookie (#19 contract, `e2e/theme.spec.ts`).
- The saved NIGHT SHIFT choice still wins on the landing: overriding it would undo the toggle the landing header itself carries. Recorded in bible 3.2 (extension) and components.md "Themes".
- Pure CSS (`:has`) instead of a proxy header or an inline script: server-rendered, no flash, no hydration mismatch on `<html>`, and a soft navigation away from `/` drops the marker so the OS decides again.

## Gotchas
- Landing e2e "dark" variants (C12, #610 C2, #99 C8) now set the `theme=dark` cookie (`useScheme`) to keep covering Night shift on the landing; a dark OS alone now shows paper.

## Evidence
- `scripts/check.sh` all green; landing + theme e2e locally (see PR).
