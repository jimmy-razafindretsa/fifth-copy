# #556 Role files route unfixed security findings to private advisories

Date: 2026-10-07. Outcome: delivered (PR #585, Deliver verdict pass, C1-C5 ticked). Docs only.

Decisions:
- Builder, Sweep and any role filing a `discovered` card for an unfixed security finding write the details to a draft private security advisory. The card gets a neutral title and the advisory id, or "details with the human" (PROTOCOL 8).
- Explorer has no advisory access. It names only the attack surface in the public BRIEF, sends weakness details to the human, and labels the card `pentest`.
- Deliver: a PENTEST with `blockers` or `majors` above 0 and `advisory: pending` gets `needs-human`, never a pass. A pending advisory with minors only may pass. The HANDOFF then says only that minors are with the human, never what they are (pentester.md: minors are never named publicly).
- PROTOCOL 10 lets builder/ui and sweep create draft advisories only. They may not publish them or add people to them.
- The PENTEST header format is unchanged, so the `blockers:` gate parser in `scripts/lib/flow.ts` still reads it.

Gotchas:
- Local `check.sh` unit runs fail on timing tests (#548 is-clean, rename-user 5 s timeouts) when the machine is under heavy load (load average above 100). CI `check` on the PR head passed.

Follow-ups (not filed; Deliver cannot create cards):
- A security finding that Deliver itself finds in review, outside any PENTEST, still has no private path. Deliver cannot create advisories, and its blocker HANDOFF to the Builder is a public comment.
- builder.md step 7 says the card carries "only" a title and the advisory id. sweep.md allows a Contract that names no attack. The two could be aligned.
