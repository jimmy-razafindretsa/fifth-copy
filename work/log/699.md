# #699 Size web join and token limits for a class behind one network

- Date: 2026-10-29. Outcome: delivered (Deliver verdict pass, PR #700). A class of 100 cookie-less students behind one IP can join one lobby and mint their first race tokens within a minute; code guessing stays at 20 distinct codes per subject per 60 s.
- Decisions: ADR 0020 amended (Amendments, 2026-10-29): `join-by-code` 120/60 s per (subject, code), `mint-race-token` 10/60 s per guest, `mint-race-token-new-guest` 120/60 s per (IP, code), shared `lobby-codes` budget 20 distinct codes/60 s per subject, checked before any lookup. `@fifth-copy/limiter` gains a read-only `count()` (ZCOUNT, no write, no key created): `limit()` records every allowed call, so without it a code refused by the budget could not stay unadmitted. Race server untouched; fail open, TTLs and `subjectKey` unchanged.
- Gotchas: `code()` is three Redis calls (read marker, spend budget, set marker). Concurrent first calls of one (subject, code) each spend a budget slot: 100 simultaneous first calls admit 20 (sequential ones all pass). Over-refusal only, never an under-count. ADR 0020 frontmatter `rule:` and the package README still describe only `limit()` / one script; the amendment line is the reference.
- Follow-ups: #701 (atomic admission under concurrency, Hardening).
