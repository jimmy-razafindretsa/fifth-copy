# #459 deploy-smoke prints 000 once for an unreachable host

Date: 2026-10-04. Outcome: C1-C5 verified by Deliver (PR #470), 5 of 5 ticked. `check()` in `scripts/deploy-smoke.sh` now masks curl's exit (`|| true`) and defaults the status to `000` only when curl printed nothing, so an unreachable host reports `-> 000 (want ...)` once per probe instead of `000000`. Exit code, `PASS`/`FAIL` lines and the three probes are unchanged.

## Decisions
- No ADR proposed. ADR 0012 (accepted) governs; ADR 0004 (proposed) covers Vitest over `scripts/**/*.test.ts`.

## Gotchas
- `scripts/deploy-smoke.test.ts` spawns the script with async `spawn`, not `spawnSync` as the C3 parenthetical says: a synchronous child blocks the event loop, so the in-process `http` stub never answers and curl times out with `000`. C3 ticked on the four behaviors and exit codes.
- Reverting the fix makes only the unreachable case fail (count 0): the stub-curl case guards the empty-output fallback.
- C1/C2 commands assume nothing listens on `localhost:3299`; the Vitest case uses an ephemeral port.
