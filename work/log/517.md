# #517 Race server: cap race-token age, write room TTLs atomically

Date: 2026-10-06. Outcome: delivered (PR #535). Deliver verified C1-C6: vitest socket 38/38, rooms 22/22; reverting `race-token.ts` and `registry.ts` to `main` fails the 9 new tests; CI (check, e2e, migrations, visual) green on head 607cbfa. PENTEST clean.

## Decisions
- No ADR. Verifier enforces ADR 0009's 5-minute lifetime: `requiredClaims: ["exp","iat"]`, `maxTokenAge: RACE_TOKEN_TTL_S`, and `exp - iat <= RACE_TOKEN_TTL_S` (jose does not bound lifetime). No clock tolerance (one host clock, ADR 0012).
- Registry writes go through `withTtl(lobbyId, multi)`: one MULTI/EXEC with both EXPIREs; EXEC `[err, value]` errors are rethrown. `open` uses HSETNX per field, so it also completes a half-written hash.

## Gotchas
- `leave` keeps HDEL/DEL outside the MULTI: they cannot create a key or clear a TTL, so the C5 spy only covers HSET/HSETNX/HMSET.
- Under heavy load the local unit step fails on two timing tests this card does not touch (`is-clean` 200 ms perf, `deploy-smoke` 5 s); CI is the reference.
