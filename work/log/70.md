# #70 First-race keyboard layout prompt (bundle with #60 avatars: portrait, crop and upload dialog)

Date: 2026-11-09. Outcome: built (ui), PR open, awaiting Deliver.

## Decisions
- No ADR. Follows 0001, 0010, 0014, 0015. Bible extensions in the PR: 7.4 "Docket dialog" (the one modal pattern: native `<dialog>`, focus wrap, Escape = secondary, 480px sheet), its first-race prompt and picture dialog sub-bullets, 10.1 "Flat portrait" (four hashed cap variants, header docket square).
- One `DocketDialog` (identity feature) serves both cards; no new `src/components/ui` primitive (#60 C3).
- The prompt mounts first in the lobby DOM so focus resumes at the top of the page; it is snoozed per browser session (`sessionStorage fc_layout_prompt=later`).
- `/settings?dialog=avatar` (outside production) and `/design?dialog=layout` open the dialogs for eyes and specimens.

## Gotchas
- e2e: the prompt would block every lobby/race spec, so `e2e/fixtures.ts` snoozes it unless the test carries `@layout-prompt`.
- e2e: `deleteUsers("")` was `LIKE '%'` (wiped every user when an afterEach ran with an unset name); the helper now refuses prefixes under 3 chars. Guest names in avatar specs avoid the generated-name words (a 3-digit generated `Heron-123` prefix-matches `Heron-1234`).
- The fake moderator (ADR 0015) is refused in production and not set in CI: Playwright sets `AVATAR_MODERATOR=fake` only for the local dev server; the blue/red verdict tests skip on CI.
- Playwright does not expose multipart bodies with files: C4 reads the crop field off the action's FormData via a fetch spy.
