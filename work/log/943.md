## Decisions
- No ADR. Follows 0001, 0006, 0008, 0009, 0010, 0013, 0016, 0017, 0021. Bible: new 14.5 "Home menu (extension, #943)" and 14.2 "Locker in the app (extension, #943)"; mockups in `docs/design/bible/screenshots/home-menu-{play,rooms}.png`, listed in 16.
- Loaders go in as props from the route (`src/app/_components/home-view.tsx`): landing components never import `lobby/server` or `stats` queries. `getMissions` is wrapped in React `cache` so the docket and the star cell share one read.
- `stageView` lives in `src/components/ui/stage-view.ts` (pure); the WebGL2 probe hook in `use-webgl2.ts` ("use client": a hook in the ui barrel breaks every server import otherwise).
- The stage paints the `sun-rays` recipe with its ray ink set to `band` on a `primary` ground (the mockup's red half).

## Gotchas
- Running e2e against `next dev` with mobile and desktop projects in parallel gives page reloads (`ERR_ABORTED GET /`) from on-demand compiles; use a production build (`CI=1`) for a clean local run.
- The locker's mark-seen action re-renders the route with a new action reference: run it once per visit (ref guard) or it loops.
- C22: the e2e asserts `>= 2` online (shared race server); the exact sum and the unanswered case are unit-tested.
