# #56 Merge transaction (guest history into an account)

Date: 2026-11-03. Outcome: delivered, Deliver verdict pass (PR #798). Pentest clean (0/0).

## Decisions
- No new ADR (0009, 0002, 0001 hold). `mergeGuestInto` locks both User rows `FOR UPDATE` in id order, refuses to run (before any write) when a User-related model has no step, runs the steps, deletes the guest.
- C3 names `Prisma.dmmf`, which Prisma 7 removed. `coverage.test.ts` reads the generated client's `_runtimeDataModel` (same models and fields) and asserts it equals `Prisma.ModelName`, so a future Prisma change fails loudly instead of passing empty. Verify command unchanged.
- `src/server/db-models.ts` exposes `Prisma.ModelName` as plain strings so the merge code outside `queries/actions/jobs` needs no generated-client import (dependency-cruiser `prisma-only-in-server`).
- Lobby and results own their steps (`merge-step(s).ts`, imported by their `index.ts`).

## Gotchas
- Callers (#39, #40, #50) must load `@/features/lobby` and `@/features/results` before merging, or the merge throws; `src/server/auth` cannot import features, so it needs an injected merge callback.
- The merge tests mock `@/env`: CI has no `AUTH_SECRET`/`RACE_TOKEN_SECRET`, and `dotenv/config` hides that locally.

## Pentest notes (non-findings)
- The rollback compensation deletes the account's avatar files at the guest's version; the account had no avatar key on that path, so only stray files of that version can go.
- Callers could take a branded guest-id type (proven by the signed `fc_guest` cookie) instead of a bare string.
- `Lobby.hostUserId` moves to the account while a live Redis room may still name the guest as host until the room ends.
