# #786 Auth.js v5 config, Credentials provider, adapter wrapper and /api/auth route

2026-11-03. Auth.js v5 (`next-auth@^5.0.0-beta.32`, v5 is published on the `beta` tag only) runs in `src/server/auth/auth.ts`: JWT sessions (30 days), the Credentials provider over `verifyCredentials` (#38), and `createAuthAdapter` over `User` + `OAuthAccount` that never reads or writes an email. `/api/auth/*` is served by `src/app/api/auth/[...nextauth]/route.ts`.

Decisions: none beyond ADR 0009. `trustHost: true` (a production build otherwise answers UntrustedHost behind Railway's proxy). `verifyCredentials` now also returns `tokenVersion` (same query) so the JWT takes it from the row.

Gotchas:
- Auth.js v5 answers a signed-out `/api/auth/session` with `null`; `handlers.GET` maps that body to `{}` (C4). `next-auth/react` would read `{}` as a session; we render sessions on the server.
- Vitest must inline `next-auth` (`server.deps.inline`): it imports `next/server` without the `.js` Node ESM needs.
- Auth.js logs a `CredentialsSignin` stack for every wrong password; keep `debug` off (debug logs the callback body, password included).
- The e2e seeds `DATABASE_URL` (the DB the web server reads), like the other e2e helpers.

Follow-ups: none filed (throttling is #87, session resolver is the next split card).
