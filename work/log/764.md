# #764 Race-server lifecycle test: desk order depends on concurrent join order

2026-11-03. Outcome: the `room()` helper in `services/race-server/src/rooms/lifecycle.test.ts` waits for the host's `welcome`, then for each guest's `welcome` before the next guest connects, so desks are host 1, `usr_p0` 2, `usr_p1` 3 on every run. The fixed-order `desks` assertions (signed `/api/internal/races` request and the fixture web API call) are unchanged.

Root cause: test, not server. The registry seats members in join-arrival order (first joined, first seated), which is the intended rule. The harness `connect` returns the socket before its handshake and join run, and the helper connected the guests back to back without waiting, so the two joins raced on the server and could land swapped. The desk allocator is untouched (C2).

Decisions: sequence the joins in the helper rather than sort the assertion, so the tests still check the exact desk each user gets.

Verify: `npx vitest run services/race-server/src/rooms/lifecycle.test.ts` 10 runs in a row, 10/10 green (29 tests each); `scripts/check.sh` all green.

Follow-ups: none.
