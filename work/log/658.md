# #658 Race server: members who dropped during a race are released at race end

Date: 2026-10-24 (built 2026-10-23, PR #666). Outcome: Deliver pass. After a non-void race ends, every member seated through a socket on this process that now has none leaves the room through the same path as a disconnect (`players/leave.ts`: `leaveRoom`, `releaseDropped`), so the last human leaving closes the room and `onClosed` frees the desks, presence, idle and ticker state.

## Decisions
- No ADR. Inside ADR 0008's room model; no new Redis key, no wire change.
- Void races keep their members: `lose` already ran `onClosed` (in-process state freed) and they reconnect to read `ended { void }` (#204).
- Only users seated through a socket on this process are released (`presence.dropped`); members written straight into the registry (rehydrate tests) are left alone.
- A line-cut member still inside the 2 min grace at race end is released too (contract C1); their resume key goes with `presence.left`.

## Gotchas
- `releaseDropped` is started from `onRaceEnded`, inside the ending's room queue, and not awaited: its own `withRoom` runs after the ending. Awaiting it there would deadlock the room queue.
- Deliver review: PR was opened without PICKUP/BRIEF/HANDOFF; PICKUP posted after the fact (hash 48773ad4a20a matched). New tests fail with the `app.ts` change reverted; C3 fails if connected members are released.
