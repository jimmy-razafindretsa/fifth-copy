# #623 Persist the per-desk text overlay on stored race results

Date: 2026-11-03. Outcome: built (Builder), awaiting Deliver.

## Decisions
- `internalRaceResultSchema.overlay: textOverlaySchema.nullable()` (bounded by `MAX_OVERLAY_WORDS`). Wire change: `PROTOCOL_VERSION` 8 -> 9; `INTERNAL_HMAC_TEST_VECTOR` body and signature recomputed (HMAC-SHA256 over `${timestamp}.${nonce}.${body}`). Web and race server deploy together.
- `buildResults` sends the desk state's raw overlay: `null` when never hit, verbatim otherwise; an empty `{extra:[],removed:[]}` is sent as is.
- `RaceResult.overlay Json?`, migration `20261103172758_race_result_overlay` (nullable JSONB, no backfill). `null` is written as `Prisma.DbNull` (a JS `null` is refused on a `Json?` column) and reads back as `null`.
- `storedEffectiveText({ textContent, overlay })` (`src/features/results/replay-text.ts`, exported by the feature index): parses the stored JSON with the protocol schema and throws on garbage, normalises the raw base text, then `effectiveText`.
- `maxStoredTraceKeys` is unchanged (still bounds by the largest overlay the wire allows); tightening it to the stored overlay is ADR 0016's follow-up.

## Gotchas
- Importing `src/features/results/index.ts` in a unit test reaches `@/server/db` and `@/env`: mock both (`replay-text.test.ts`).
- A results outbox entry queued by a protocol-8 race server fails to parse after the bump (same hazard as every bump).
