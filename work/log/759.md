# #759 Board gates: Done requires QA; QA accepts a merged PR

2026-11-03. `gate <n> Done` now refuses any card whose Status is not QA; `gate <n> QA` accepts an OPEN or MERGED PR (closed-unmerged still fails).

Root cause on #651: three things.
1. The REST-posted `HANDOFF deliver` had a blank line between the signature line and `verdict: pass`. PROTOCOL 9 reads fields only from the header block (signature up to the first blank line or fence), so the verdict was invisible. Author (trusted owner) and ordering (after the newest PICKUP) were fine. The strict header rule is an anti-forgery control and stays; the QA gate now prints an extra line naming a HANDOFF deliver with no header verdict.
2. The QA gate required `pr.state == OPEN`, so a card whose PR merged before a re-pick could never reach QA.
3. The Done gate never looked at the current Status, so In Review -> Done skipped QA.

Gotcha: when posting HANDOFF/PENTEST via REST, put the fields directly under the signature line, no blank line.

Decisions: none (no ADR). Follow-ups: none.
