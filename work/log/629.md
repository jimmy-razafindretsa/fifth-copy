# #629 e2e: landing waits and worker count under machine load

Date: 2026-10-24. Outcome: delivered (PR #667). Deliver (fresh context) verified C1-C5: landing spec 96 passed idle; `PW_WORKERS=1` header `using 1 worker`; `E2E_TIMEOUT_SCALE=3 PW_WORKERS=2` passed 3 runs (3.0m, 3.1m, 3.9m) with `scripts/check.sh` looping alongside (load avg up to 16 on 4 cores); a missing hydration-gate selector fails with `Timeout: 30000ms` (and `90000ms` at scale 3), no hang.

## Decisions
- `e2e/timeouts.ts` owns e2e test waits: `scaled(base)`, `HYDRATION_WAIT`, `ACTION_WAIT`. New specs import it instead of literal timeouts.
- Playwright `timeout` and `expect.timeout` also go through `scaled()` (defaults unchanged at scale 1). CI workers and retries are unchanged.
- An invalid `PW_WORKERS` (e.g. `abc`) falls back to the Playwright default.

## Gotchas
- Running `scripts/check.sh` and e2e in the same worktree at the same time fails the unit step (`services/race-server/src/rooms/rehydrate.test.ts` count reconciliation). The e2e race server and the unit tests share the worktree's Redis db index. This is unrelated to load and to this diff. check.sh is green when run alone.

## Follow-ups
- Suggested Hardening card: give unit tests a Redis db index separate from the worktree's e2e race server (not filed: the cloud session had no board access).
