# #675 Room-code helpers: one zod-free definition in the protocol, drop the lobby copy

Date: 2026-10-31. Outcome: delivered (PR #719). Deliver verified C1-C3. No pentest (pure refactor).

## Decisions
- No ADR. Consistent with ADR 0005 and 0006: the zod-free module stays in `@fifth-copy/protocol` and the protocol still imports only zod and engine.
- `@fifth-copy/protocol/room-code` is a declared `package.json` subpath export pointing at `room-code-format.ts`. Client code imports it so it never evaluates the barrel, which builds zod schemas at module load. The barrel still exports all four names.
- `RoomCode` is declared in `room-code-format.ts` as `string & z.$brand<"RoomCode">` (type-only zod import) to avoid a depcruise type-only cycle. A unit test pins it equal to `z.output<typeof roomCodeSchema>`.

## Gotchas
- `room-code-format-zod-free` (depcruise) rejects every runtime import from that module, not only zod. Deliver probe: a runtime `zod` import and a runtime `./version` import each fail `boundaries`.
- First-load scan (Deliver): `/` and `/lobby/[code]` are 151.1 kB gzip, no zod signatures in their 9 first-load chunks, the room-code regex is present; zod still exists in another client chunk (positive control).
