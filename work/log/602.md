# #602 CI e2e shards restore Chromium from a cache keyed by the Playwright version

Date: 2026-10-28 (build, workflow push, Deliver review + QA). Outcome: PR #677, Deliver verdict pass. The `e2e-shard` job reads the installed `@playwright/test` version into a step output and restores `~/.cache/ms-playwright` with `actions/cache@v4` keyed `playwright-${{ runner.os }}-<version>` before the unchanged `npx playwright install --with-deps chromium` (now `timeout-minutes: 5`).

## Decisions
- No ADR (governing 0003, 0004, 0012). Cache route, not the pinned `visual` container (BRIEF: bigger pull, different service hostnames).

## Evidence (CI run 40730269134 on 259809d)
- Attempt 1: all four shards `Cache not found for input keys: playwright-Linux-1.63.0`, downloaded Chrome for Testing; shard 1 saved the key, shards 2-4 logged "Unable to reserve cache" (harmless race). Install step 17-37 s.
- Attempt 2 (re-run): all four shards `Cache restored from key: playwright-Linux-1.63.0`, no Chromium download, install step 9-32 s (OS packages only).

## Gotchas
- The builder's token lacked `workflow` scope, so the ci.yml commit was pushed from another session (259809d).
- Cache entries are branch-scoped: main saves its own entry on its first run after merge (one more miss there), and PR branches then read main's.
- apt stalls inside `install-deps` are not covered; the 5-min step timeout bounds them.
