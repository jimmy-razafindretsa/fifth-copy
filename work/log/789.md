# #789 Teacher password reset: /reset screen and redeem action

2026-11-04. A student redeems a teacher-issued code on `/reset`: password set, `tokenVersion + 1`, code consumed, recovery code untouched.

Decisions: the redeem lives in `src/features/identity/actions/redeem-password-reset.ts`; the attempt is counted on `password-reset-redeem` per `reset:<usernameNormalized>` and per `requestSubject()` before the one lookup and the one Argon2id comparison (`DUMMY_HASH` on a miss). The consume is a guarded `updateMany` (unused, unexpired, still the newest row) inside the transaction, so two concurrent redeems spend a code once. Success does not sign in; it links to `/sign-in`. Bible 14.3 gains "Password reset screen".

Gotchas: `DUMMY_HASH` is now exported from `@/server/auth`. A form whose `action` is a function must not set `method` (React warns); the server action makes it POST before hydration anyway.

Follow-ups: none.
