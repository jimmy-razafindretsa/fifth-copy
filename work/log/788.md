# #788 Teacher password reset: PasswordReset model and host-issued code

2026-11-04. The host of a lobby, if it is an account the owner flagged as a teacher, can issue a single-use, 30-minute reset code for a student who raced in any of their lobbies; only its Argon2id hash is stored and the row is the audit record.

- Migration `20261104003650_password_reset` (additive: `User.isTeacher` column, one table, two indexes, two FKs; regenerated before merge after the owner's teacher-flag decision). An extra index on `issuedByUserId` backs the `SET NULL` FK.
- Eligibility lives in `src/features/identity/queries/reset-eligibility.ts` (not `password-reset/` as the card sketched): the Prisma client is only allowed in `queries|actions|jobs`.
- Order inside `issuePasswordReset`: zod (no control characters), viewer + one lobby query (host, not a guest, `isTeacher`; else `not-host`), `password-reset-issue` limit (refusals count), ONE student query `findResetTarget` (every refusal the same `not-eligible`), hash, insert. Lookup errors refuse, never throw.
- `User.isTeacher` is written only by `scripts/grant-teacher.ts <username>` (owner, out of band).
- Guest merge: `guestHasNone("PasswordReset")` (subject or issuer), as for the recovery code: a guest can never own one.
- For R2: redeem the newest unused, unexpired row of the user (`@@index([userId, issuedAt])`), verify with `verifyPassword(normalizeResetCode(input), codeHash)`, bump `tokenVersion`.
