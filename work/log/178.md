# #178 Presence, reconnection grace, resume key

- Date: 2026-10-07. Outcome: delivered (PR #603), Deliver verdict pass; 6 of 6 contract items verified.
- Decisions: no ADR. Resume keys are `resume:<key>` (string) plus a per-room index `room:<id>:resume` (hash), both TTL'd in the same MULTI as their write (ADR 0008); the key is read at the handshake only after the race token and room checks, only in countdown/running, and resumes only when bound to (token.lobby, token.sub) (ADR 0009). The desk always comes from membership, never from the key. `GRACE_MS` (120 s, 12 s fast clock) is in `rooms/durations.ts`.
- C3: read with #161's engine tiers (`asleep` shares the unfinished tier with `expired`, ordered by progress; only `abandoned` is last). The fixture gives the asleep desk lower progress; the engine is untouched. #183's text carries the same wording.
- Earlier tests changed on purpose: #165 welcome now carries a hex `resumeKey`; #166 disconnect during running is a line cut (desk kept); room close mid-race now comes only from `onRoomClosed` (members never leave mid-race), plus an ended-phase close test.
- Gotchas: a room where everyone drops mid-race ends at grace expiry and lingers to its TTL; grace timers are in-process (restart voids them, #204); a reconnect after the 300 s token TTL needs a fresh token (#215/#235). The index hash TTL is set only at issue, not refreshed by `keep`.
- Follow-ups: none filed.
