# #32 Automatic guest identity on first write: typist name, signed cookie

Date: 2026-10-05. Outcome: C1-C9 verified by Deliver (PR #512), 9 of 9 ticked. `ensureGuest()` (server-only, not a Server Action) creates one guest `User` per browser and sets `fc_guest` = `<userId>.<base64url(HMAC-SHA256(userId, AUTH_SECRET))>`. The guest resolver is the last link of the `getViewer()` chain and is read-only. Pentest: 0 blockers, 0 majors, 2 minors.

## Decisions
- No ADR. ADR 0009 left the cookie format open; the card body sets it. Stored names are bare (`Sparrow-482`); the UI adds Comrade/Camarade (bible section 2 note).

## Gotchas
- `AUTH_SECRET` (>= 32 chars) is now required by the web app, including at `next build` time. Old `.env` files need it, and so does the production image build.
- `getViewer()` now imports `next/headers`, `@/env` and `@/server/db` through `resolvers.ts`. Unit tests of the default chain must mock all three (see `src/server/auth/viewer.test.ts`).
- The resolver's cookie clear is best-effort: Next throws on `.delete` during Server Component render. The real clear happens when `ensureGuest()` overwrites the cookie.
- Two tabs doing their first write at the same moment can create two guests. The last Set-Cookie wins. Accepted for the MVP.
