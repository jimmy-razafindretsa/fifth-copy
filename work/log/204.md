# #204 Room recovery after restart: rehydrate or void rooms

Date: 2026-10-07. Outcome: Deliver pass, 6 of 6 contract items verified (PR #612).

## Decisions
- No ADR: implements ADR 0008 "Restart behaviour" as written. Only `room:<id>` and `room:<id>:members` are read back on boot; the desks mirror and trace lists are never read for recovery (a `countdown`/`running` room is voided and they are deleted).
- `rooms` index set (no SCAN): SADD in `open`'s MULTI, `expire rooms` in `withTtl` so the index outlives every room, SREM in the close MULTI. A voided room keeps `raceId` and members, both hashes get `VOID_TTL_S` = 300 s.
- Redis loss is detected by `EXISTS room:<id>` at the end of the flush MULTI (alone every `LOST_PROBE_MS` = 1 s when nothing is dirty). A Redis error never voids: only a missing hash does (flush rejection, reconcile error and per-room rehydrate error are logged and retried).
- `createRaceServer({ recovery })` defaults to true (production `main.ts` passes nothing). Off in the test harness by default and in `internal.test.ts`, because the shared test db's `rooms` set lists other test files' live rooms; `rehydrate.test.ts` turns it on in its own keyPrefix. Accepted as a test-isolation hook.

## Gotchas
- A reconnect (join) to a voided room refreshes its TTL to `ROOM_TTL_S` (1 h) like any activity, so it lingers like a normal ended room; documented in the README. Accepted as minor: #143's "Race again" resets the room.
- If `rehydrate` cannot read the index at boot (Redis down), `listen()` rejects and the process exits: fail-fast, the supervisor restarts it.
- Harness trace cleanup with a keyPrefix: `KEYS` takes and returns full names (ioredis does not prefix patterns).

## Follow-ups
- #613 voided races leave an open-ended `Race` row (created at `host:start`, never ended because voids persist nothing); not covered by #143.
- #600 timing tests: `check.sh` unit step was green here; `is-clean` and `lifecycle` also green alone.
