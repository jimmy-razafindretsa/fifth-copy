# #704 Race-server deploys must not cut live races on Railway

Date: 2026-11-04. Outcome: built (C1-C3, C5); C4 is the owner's live test on production, pending.

## Decisions
- Drain on SIGTERM, not a manual deploy trigger (ADR 0019 Consequences). Cap `RACE_DRAIN_CAP_S` 900 s; Railway draining 930 s, overlap 0 (`services/race-server/railway.json`).
- Owner lease (`instance:<id>`, 30 s TTL): Railway boots the new deployment before it SIGTERMs the old one, and a boot used to void every live race (ADR 0008). A boot now voids only races whose owner's lease is gone.
- While draining, rooms with no live race and no socket on the process stop counting, so the drain ends after the last race instead of at the cap.

## Gotchas
- Railway Config as Code files stop being read on 2026-12-01; the durable setting is the service variables `RAILWAY_DEPLOYMENT_DRAINING_SECONDS` and `RAILWAY_DEPLOYMENT_OVERLAP_SECONDS`. The race server warns at boot when the draining time is below its cap.
- The docs state no maximum draining time and do not promise WebSockets to the old deployment survive the switch: C4 checks both.
