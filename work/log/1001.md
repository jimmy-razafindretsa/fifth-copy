## Documented event sequences

Sources fetched and checked on 2026-11-20. What they settle, and what they do not:

- UI Events §4.3.2 "Dead keys" (https://www.w3.org/TR/uievents/#keys-dead): a dead key's `key` is `"Dead"`; "in response to any dead key press, composition events must be dispatched by the user agent", with the example keydown `Dead`, `compositionstart`, `compositionupdate` U+0302, keyup `Dead`, keydown `ê`, `compositionupdate` `ê`, `compositionend` `ê`, keyup `e`; it also says "the MacOS and Linux operating systems use input methods to process dead keys".
- UI Events §4.3.4 "Default actions and cancelable keyboard events" (https://www.w3.org/TR/uievents/#keys-cancelable-keys): a dead-key example on a French mapping with no composition events (keydown `Dead`, keyup `Dead`, keydown `e`, `beforeinput` data `e`, `input`, keyup `e`), where the dead key's default action is prevented, so the result is a plain `e`; and the plain-key example (keydown `Q`, `beforeinput` `Q`, `input`, keyup `Q`).
- UI Events KeyboardEvent key Values §3.8 (https://www.w3.org/TR/uievents-key/#key-Dead): the key value is `"Dead"`, and "the associated compositionupdate event's data attribute provides the specific key value", which implies user agents may also fire composition events.
- Input Events Level 2 §7 (https://www.w3.org/TR/input-events-2/#input-event-order-during-composition): after each `compositionupdate`, a non-cancelable `beforeinput` / `input` pair with `inputType` `"insertCompositionText"` and the update's `data`; the current draft defines no `deleteCompositionText` or `insertFromComposition`.
- MDN KeyboardEvent.key (https://developer.mozilla.org/en-US/docs/Web/API/KeyboardEvent/key): a dead key's value must be `"Dead"`. MDN documents no per-platform or per-browser dead-key difference.
- Microsoft, About Keyboard Input, Dead-Character Messages (https://learn.microsoft.com/en-us/windows/win32/inputdev/about-keyboard-input): Win32 delivers a dead key as `WM_DEADCHAR`, then one `WM_CHAR` with the accented letter. It says nothing about browser events.
- Apple, mac-help mh27474 (https://support.apple.com/guide/mac-help/enter-characters-with-accent-marks-on-mac-mh27474/mac): dead keys in general (Option-N then a for ã) and the Keyboard Viewer; no per-key list, no browser events.

So the specifications document two event models: composition (§4.3.2, Input Events §7) and a `Dead` keydown without composition events (§4.3.4, shown only with the dead key cancelled). No source says which OS or browser uses which model. Every row below that names a model for an OS or browser is marked "undocumented: assumption", and `composeKeys` handles both models on every row. A direct accented key (no dead key) follows the plain-key example of §4.3.4 on every system.

## Findings

- No race text can be set by the host, so C5 types up to the first `ê` of a French practice-letter race (Block mode) instead of a text that starts with `ê`; the cursor stands on `ê` either way.
