# #557 Race wire contract (protocol v4)

- Date: 2026-10-07. Outcome: Deliver pass. `@fifth-copy/protocol` v4 (one bump, 3 -> 4) declares every live-race wire shape (race events, snapshots, spectator role, `resumeKey`, internal start/results payloads); the race server emits the v4 `welcome`/`roster` and the lobby store parses them. PR #582.
- Decisions: `MAX_RACE_MS` = 1 h caps every ms-since-GO field. The spec allows untimed races (the race ends when everyone finishes), so the bound is a wire safety cap, not a game rule: 500 words at 10 WPM is 50 min. #166 must end a race by `MAX_RACE_MS` (note posted on #166). Spectator tokens are refused as `bad-token` until #187.
- Gotchas: `nameSchema` (64 chars, no control/format/bidi code points) also applies to the race-token `name` claim. Today names are only generated guest names. A later card that lets users choose a display name must validate it with `nameSchema`, or the handshake refuses that user. `welcome.room.phase` is still always `waiting` (the registry writes it at open; #166 changes it).
- Follow-ups: #189 must raise the 64 KiB internal body cap for the results route or chunk traces (pentest minor 4). #101 (PR #581) edits `registry.ts`, `server.ts`, `lobby-store.test.ts` and the race client `socket.test.ts`, so whichever merges second rebases.
