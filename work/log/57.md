# #57 Merge confirmation stamp

Date: 2026-11-04. Outcome: built (UI); Deliver pass 2026-11-04.

## Decisions
- No new ADR (0010, 0001 hold). `MergeStamp` (server, root layout) reads `fc_merged`; the client docket clears the cookie with `document.cookie` in its first effect. Next 16 cannot delete a cookie while rendering, and a Server Action delete would refresh the layout and unmount the stamp. The value is only a race count, so the cookie is not httpOnly; it lives 60 s.
- Stamp primitive (#26) is on main: ink tone, `FILED` / `CLASSÉ` + `N RACES CARRIED` (bible 7.4 "Merge stamp docket", added in this PR). The second line also matches #55's "1 race carried" (Playwright getByText ignores case).
- `scripts/see.ts` takes `SEE_COOKIES="fc_merged=3"` to show one-shot states.

## Gotchas
- No caller sets the cookie yet: sign-up and sign-in #36 and OAuth #49 (#39, #40, #50 were closed as not planned) must call `flashMerge(counts)` (identity index) after `mergeGuestInto`, before redirecting, and re-render the root layout (a full redirect or `revalidatePath("/", "layout")`).

## Follow-ups
none

## Deliver
- Root layout already read cookies (`getLocale`, `getTheme`), so every route was dynamic before; `MergeStamp`'s `cookies()` read adds no rendering mode change (Next 16.3 docs: cookies in a layout opts into dynamic rendering).
- `fc_merged` holds only a digit count (parsed `^\d{1,7}$`, max 1,000,000), is read only by `MergeStamp` to render a cosmetic stamp to its own holder, and is never trusted for anything else.
- The end-to-end proof that a real merge shows the stamp is #55 C1 ("1 race carried").
