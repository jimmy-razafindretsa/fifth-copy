# #809 Invite route, refusal screen and the host's link row (R213)

Date: 2026-11-10. Outcome: built (ui); awaiting Deliver.

## Decisions
- No ADR. Follows 0001, 0009 (GET peeks, the `TAKE YOUR DESK` form post consumes), 0010. Bible 14.3 gains "Invitation and refusal screens, link row (extension, #121)".
- `takeInvite` (form action) wraps `redeemInvite` and redirects with `RedirectType.replace`, so Back never returns to a spent link. The token travels in a hidden field of the invite page only.
- `closed` after a press (room started or closed) shows the landing's closed sentence as the inline error line, like `rate-limited` and `unavailable`; only `not-found` is the stamp.
- The link row shows from the viewer's own `isHost` member row; `createInvite` re-checks the host.

## Gotchas
- After the soft navigation to the lobby, the invite page's RSC payload (with the token) stays in that tab's DOM; the e2e checks the lobby's own document (`request.get`), which carries no token.
- `createInvite` builds the URL from `NEXT_PUBLIC_APP_URL`; in a worktree e2e that is the dev port, so the spec opens the URL's path on the test server.
- The R213 five-context test runs on the desktop project only (phones hide invite rows; shard balance).
