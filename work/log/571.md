Deliver verified C1-C3: `npx vitest run packages/engine/src/text` 81/81, `npx vitest run packages/engine` 185/185, README grep ok; `scripts/check.sh` format/lint/types/boundaries/adr/prisma/privacy PASS, unit only fails on the known is-clean perf flake (#548); CI green on the PR head.

## Decisions
- No ADR (0005, 0007 hold: change is pure engine data). `« » €` added to `TYPEABLE`; curly double quotes still map to `"`, `‹ ›` to `'`, NBSP / narrow NBSP to a plain space.
- `ENGINE_VERSION` 0.3.0 -> 0.3.1: README only says "bump on any change to text handling"; a patch bump for a whitelist widening fits the existing history.
- Spec 13.2 / R174 row (é è ê à ç ù œ « ») and spec 14 drill list (incl. €) are now all typeable; `…` still maps to `...` by design.

## Gotchas
- `mapChars` checks the whitelist before `CHAR_MAP`, so a `CHAR_MAP` entry for a typeable character is dead code (a mutation adding `«` back to the `"` map survives all tests, correctly). The meaningful revert (remove from `TYPEABLE` + map to `"`) fails 7 tests; dropping `€` fails 5; counting `« » €` as words fails 4.
- Protocol v4 (#557) is on main: `keystrokeSchema` accepts `«`, `»`, `€` (tsx probe on origin/main); `internal.test.ts` fixture still says `engineVersion: "0.3.0"`, harmless (any string).
