# #583 Practice letters reject control and invisible characters (settings schema)

- Date: 2026-10-07
- Outcome: Deliver verdict pass (PR #586). C1 and C2 ticked with evidence.

## Decisions
- `practiceLetterSchema` = `isTypeable(s) && /^\p{L}$/u.test(s)`. The engine whitelist (#157) is the single source; `\p{L}` drops its non-letters (space, digits, punctuation, symbols). The old NFC/length check is subsumed (the whitelist holds only single NFC code points) and was removed.
- Accepted set is exactly 84 characters: a-z, A-Z and the 32 French letters (lower and upper). Spec section 8 examples (é è à ç, q z x) and uppercase accents pass.
- Consistent with #557's printable rules (`UNPRINTABLE` in `packages/protocol/src/race.ts`: Cc, Cf, Cs, Co, Zl, Zp): every accepted character is a letter outside those classes, so this rule is strictly tighter.
- No PROTOCOL_VERSION bump: the inferred type stays `string[]`; validation-only tightening of an existing field.

## Gotchas / follow-ups
- Live rooms: a Redis room hash already holding a now-invalid letter would fail loudly in `parseSettings` after deploy. Accepted: only a host could store one (feature is recent), room keys carry a TTL.
- A future client practice-letter picker must offer only TYPEABLE letters (no consumer in `src/` yet).
