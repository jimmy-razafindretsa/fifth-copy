# #207 Shared Redis-backed rate limiter for web actions and socket messages

Date: 2026-10-29 (build, two pen-test rounds, Deliver review + QA). Outcome: PR #698, Deliver verdict pass. New workspace package `@fifth-copy/limiter` (one Lua sliding window over an injected `eval` client, keys `${prefix}:rl:${key}` with a TTL of one window); the race server guards every client event per token identity before any handler (fails closed); the web app throttles `joinByCode` and `mintRaceToken` through `src/server/limiter` (fails open).

## Decisions
- ADR 0020 accepted by Deliver (consistent with 0005, 0006 point 7, 0008, 0009, 0012). Owner approved `ioredis` in web and the package (DECISION on #207).
- Race-server buckets are per identity (lobby, seat or spectator, `sub`), not per socket id: stricter than the contract wording, from the pen test. At most 4 sockets per identity per process.
- Web subject: guest cookie, else the last `X-Forwarded-For` hop (`TRUSTED_PROXY_HOPS = 1`, one Caddy per ADR 0012). Adding a proxy hop means changing that constant.

## Gotchas
- Playwright starts the web server with `REDIS_URL=""`: the whole suite is one IP. Limiter behaviour lives in vitest (C1-C3).
- Throttled joins and mints show the generic error until #120 adds a throttled state.
