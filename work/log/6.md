# #6 Playwright harness, see.ts eyes, visual test config

Date: 2026-10-03. Outcome: delivered (PR #454); all three contract criteria verified by Deliver. The harness already on `main` (`e2e/fixtures.ts`, `playwright.config.ts`, `scripts/see.ts`, `scripts/visual-baselines.sh`) met the contract; this PR adds a regression test and a hazard note.

## Decisions
- No ADR proposed in this PR. ADR 0004 (tooling baseline) stays proposed for #5.
- `scripts/see.test.ts` pins the see.ts host allowlist (example.com, `localhost.evil.com`, `localhost@evil.com`, `127.0.0.1.nip.io`, non-local `SEE_BASE_URL`): exit 2, no `.eyes/` write. It runs in `scripts/check.sh` unit.

## Gotchas
- In a worktree, export `DATABASE_URL` (local DB) before e2e or see.ts: the dev server's `/api/health` queries it.
- e2e uses `next dev -p 3100` with `reuseExistingServer` locally: a server already on :3100 from another worktree gets reused. see.ts expects a server on :3000; do not run two `next dev` in one worktree at once (`.next/dev` clash).
- Fixtures tolerate 4xx (so specs can assert 404 pages); see.ts fails on any status >= 400. The axe tags and listeners are duplicated on purpose.
- The `@visual` suite needs the pinned Docker image; CI job `visual` covers it.
